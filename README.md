## 📌 GitHub 브랜치 전략
- `main` : 완성된 코드만 모아두는 브랜치 (👉 함부로 수정 ❌)
- `develop` : 기능 개발 통합 브랜치 (👉 여기서 대부분 작업)
- `feature/기능명` : 각 기능별 작업 브랜치  
  - 예: `feature/frontend-ui`, `feature/posture-rule`, `feature/ml-model`

👉 **기본 원칙**
1. **새로운 작업은 항상 `develop` 브랜치에서 시작한다.**  
2. **기능별 브랜치를 만들어 작업한다.**  
3. **작업이 끝나면 `develop`에 Pull Request(PR)을 올린다.**  
4. **전공자가 확인 후 merge 한다.**
